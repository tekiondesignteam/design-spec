Designer's Guide

From a spec to a working screen.

Describe what you want in plain language, pinned to a real design system. Claude turns it into a working, reviewable prototype and stops at every checkpoint, so it never drifts from your intent.

The idea in one minute

Small artifacts you approve one at a time.

Long AI sessions drift. Claude fills gaps with guesses and forgets decisions it made an hour ago. This workspace fights that with a chain of small artifacts you sign off on as you go. Each project lives in its own folder and is pinned to one design system, so you inherit its look instead of inventing visual style.

Get set up

A one-time, 10 minute setup.

You don't need to be technical, and you never touch a terminal. Install one free app, then ask Claude in plain English to fetch the workspace for you. Claude runs the technical bits and asks permission first, so all you do is click Allow.

tekiondesignteam / design-specgithub.com/tekiondesignteam/design-spec ↗
1

Install the Claude desktop app

This is where you'll do everything, and Claude Code is built right in, so there's nothing else to install. Download it from claude.ai/download, open it, and sign in with your work account.

One thing Claude needs to fetch the workspace: Git. Most Macs already have it. If yours doesn't, the app offers to install it the first time it's needed, so just say yes.

2

Open Claude Code and pick a folder

  • Click the Code tab at the top, then + New session.
  • Use the Project folder picker to choose where the workspace should live. Your Desktop is a fine choice. You can also drag a folder in.
3

Ask Claude to fetch the workspace

Type this to Claude and send it, word for word:

You Clone https://github.com/tekiondesignteam/design-spec into this folder, then install the pre-commit hook from its hooks/ folder.

Claude asks permission before it runs anything, so just click Allow. When it's done you'll have a new design-spec folder, and a safety guardrail is switched on that quietly keeps the shared design systems read-only. You don't need to understand it; it just protects you.

4

Point Claude at the workspace

Start a + New session and set the Project folder to the design-spec folder Claude just created. That's the workspace, and everything you build lives inside it.

5

Start building

That's the whole setup. From here you just tell Claude what you want in plain English. Two shortcuts speed up the main steps. Type them, or say the same thing in words:

  • /new-project or “start a new project called vehicle-search using the t1 design system”
  • /spec or “turn this PRD into a spec”
Next time there's nothing to reinstall. Open the app, go to Code, start a new session, and set the folder to design-spec.
The five artifacts

Everything Claude builds traces back to these.

You read and approve them; Claude fills them in. Acceptance criteria (AC-1, AC-2, and so on) are the backbone. Every task cites one, and every review frame proves one in the browser.

constitution.md

The frame

Boundaries plus the design system's visual language. Read this first.

Generated by /new-project, then you review
spec.md

The what

The problem, scope, flows, components, states, and acceptance criteria.

/spec, with your input
plan.md

The order

The build broken into small, checkpointed steps.

You and Claude together
tasks.md

The checklist

One line per behavior, each citing an acceptance criterion. It's also the drift log, where any divergence from the spec is recorded rather than hidden.

Claude, as it builds
reviews/step-N.md

The evidence

Screenshots plus checks proving each step matches the spec, at every breakpoint the design system defines.

Claude, at each checkpoint
★

If it isn't an AC, it doesn't get built.

Acceptance criteria are the contract between your intent and the pixels. That's what keeps the prototype honest to the spec.

The workflow

Build one checkpoint at a time.

  1. Scaffold the project

    /new-project <name> [design-system]

    Creates projects/<name>/ with the template files and fills the constitution from the chosen design system. Nothing gets designed yet.

    → Then: read constitution.md. Does the visual direction look right?

  2. Write the spec

    /spec <name> <your PRD>

    Paste text, a Confluence, Jira, or Figma link, or a file path. Claude scores your brief on six dimensions and only asks about the gaps. Anything you skip stays a visible {{TODO}}, never an invented requirement.

    → Then: read spec.md and kill ambiguity. Name real components, real states, real copy.

  3. Plan the build

    Ask Claude to fill in plan.md. It orders the work so each step is small and reviewable: shell first, then sections, then states (empty, loading, error, success), then polish.

  4. Build, then review

    Before each step Claude re-reads the constitution and spec; after each step it records a reviews/step-N.md walkthrough with screenshots at every breakpoint. Then it stops and waits for you. Checkpoints are where drift gets caught, so use them.

  5. Done

    A screen is done when it uses only the design system's tokens and components, every state in the spec is built, it renders at every breakpoint, and nothing outside your project folder changed.

The rules Claude follows

So you know what to expect.

▢
One folderOnly projects/<name>/ is ever modified.
◇
One design systemNo mixing, borrowing, or inventing tokens. A missing piece is logged as a gap, not faked.
⌘
One HTML filePlain HTML, CSS, and JS, or React via in-browser Babel. No build step to compile.
◑
Every state, every breakpointEmpty, loading, error, and success, all verified visually and with a DOM check.
↯
Drift is loggedIf the UI diverges from the spec, it goes in the drift log and the spec updates first.
✎
Deviations are on purposeIntentional breaks from the system are recorded in the constitution with a reason. Nothing silent.
Running & quick reference

Open your prototype, and everything at a glance.

The simplest way to view a build is to ask, then click Allow:

You Serve this repo locally and give me the link to open my prototype.

Claude starts a local web server and hands you a http://localhost/… link. Don't double-click the HTML file, because opening it directly is blocked for any prototype that loads its design-system bundle.
